- 단위마다 구현 → 해당 단위 테스트 통과 → 다음 단위. 전체 일괄 테스트로 대체하지 않는다.

- 입력 파일은 생성기가 결정적으로 만든다(고정 시드 난수, 텍스트, 16-bit PCM WAV). 각 샘플 옆에 `*.expected.json`(파일명·크기·압축 크기·플래그·SHA-256, ADPCM은 `lossy`, `(listfile)`/`(attributes)`는 `internal`)을 쓴다. 비손실 파일은 StormLib 재읽기 결과가 입력과 같은지 생성 시 확인한다.
- SC2 User Data 샘플은 StormLib가 만들 수 없으므로 생성기가 `MPQ\x1B` 헤더 + 사용자 데이터 + 패딩(헤더 0x400)을 MPQ 앞에 붙인다(MPQ 내부 오프셋은 헤더 기준이라 수정 불필요).
- 패치 샘플은 **BSD0**다. StormLib는 파일 추가 시 BSD0만 패치 파일로 인식하고(`IsIncrementalPatchFile`), 그때 BSD0 데이터를 항상 RLE 압축으로 보고 새 크기를 읽는다. 그래서 생성기는 단일 ctrl 엔트리 bsdiff(공통 길이 차분 + 나머지 extra)를 만들고 StormLib `Decompress_RLE` 형식(앞 DWORD + `0x80|(n-1)` 리터럴 / `n-1` 0 반복)으로 압축해 넣는다. `patch-1.mpq.expected.json`은 베이스+패치 체인 결과를 기록한다.
- weak 서명: Windows DLL은 `SFileSignArchive`를 익스포트하지 않으므로 `SFILE_CREATE_MPQ.dwFileFlags3 = MPQ_FILE_DEFAULT_INTERNAL`로 `(signature)`를 만들고 닫을 때 서명되게 한다.
- v2+ 아카이브는 StormLib `SCompDecompress2`의 고정 마스크(ZLIB, PKWARE, BZIP2, LZMA, SPARSE, SPARSE\|ZLIB, SPARSE\|BZIP2, ADPCM\|HUFFMANN)만 해제한다. Huffman 단독 등 임의 조합은 v1 샘플에만 둔다.
- **StormLib v9.40 sparse 버그**: `CompressSparse`는 섹터 마지막 3바이트 안에 0이 아닌 바이트가 있으면 `0xFF`(0x80바이트 청크) 마커 뒤에 1~3바이트만 쓰고, `DecompressSparse`는 입력 부족으로 거부한다. 아카이브 샘플은 섹터 끝 3바이트를 0으로 두어 피하고, 버그 케이스는 `sparse-vectors.json`에 보존한다(단위 8 참고).
- strong 서명 샘플은 Blizzard 개인키가 없어 만들 수 없다. 단위 17에서 테스트용 키 쌍으로 검증한다.

## 단위 3. StormCrypto

- **대상**: `src/.../Internal/StormCrypto.cs`
- **코드 초안**:

```csharp
internal static class StormCrypto
{
    private static readonly uint[] Table = BuildTable();

    private static uint[] BuildTable()
    {
        var table = new uint[0x500];
        uint seed = 0x00100001;
        for (int i = 0; i < 0x100; i++)
        for (int j = 0, index = i; j < 5; j++, index += 0x100)
        {
            seed = (seed * 125 + 3) % 0x2AAAAB;
            uint high = (seed & 0xFFFF) << 16;
            seed = (seed * 125 + 3) % 0x2AAAAB;
            table[index] = high | (seed & 0xFFFF);
        }
        return table;
    }

    public static uint HashString(ReadOnlySpan<char> name, MpqHashType type)
    {
        uint seed1 = 0x7FED7FED, seed2 = 0xEEEEEEEE;
        foreach (char c in name)
        {
            uint ch = NormalizeChar(c);  // ASCII 대문자, '/' → '\' (HashStringSlash는 '/' 유지 — 이름 조회용)
            seed1 = Table[((int)type << 8) + ch] ^ (seed1 + seed2);
            seed2 = ch + seed1 + seed2 + (seed2 << 5) + 3;
        }
        return seed1;
    }

    public static void DecryptBlock(Span<uint> data, uint key)
    {
        uint seed = 0xEEEEEEEE;
        for (int i = 0; i < data.Length; i++)
        {
            seed += Table[0x400 + (key & 0xFF)];
            uint plain = data[i] ^ (key + seed);
            key = ((~key << 0x15) + 0x11111111) | (key >> 0x0B);
            seed = plain + seed + (seed << 5) + 3;
            data[i] = plain;
        }
    }
    // EncryptBlock: 같은 흐름, seed 갱신에 암호화 전 평문 사용

    public static uint GetFileKey(string fileName, long blockOffset, uint fileSize, MpqFileFlags flags)
    {
        int slash = fileName.AsSpan().LastIndexOfAny('\\', '/');
        uint key = HashString(fileName.AsSpan(slash + 1), MpqHashType.FileKey);   // 경로를 뺀 파일명만
        return flags.HasFlag(MpqFileFlags.FixKey) ? (key + (uint)blockOffset) ^ fileSize : key;
    }
}
```

- 바이트 Span 버전은 `MemoryMarshal.Cast<byte, uint>`로 처리하고, 4바이트 미만 꼬리는 암호화하지 않는다(Storm 동작).
- **검증**: `StormCryptoTests` — `HashString("(hash table)", FileKey) == 0xC3AF3770`, `HashString("(block table)", FileKey) == 0xEC83B3A3`, 대소문자·`/` 정규화 동일 해시, Encrypt→Decrypt 라운드트립
- **선행 단위**: 1

```csharp
internal const uint HeaderSignature = 0x1A51504D;   // "MPQ\x1A"
internal const uint UserDataSignature = 0x1B51504D; // "MPQ\x1B"

public static (MpqHeader header, MpqUserData? userData, long headerOffset) Find(Stream s, MpqOpenOptions options)
{
    for (long pos = 0; pos + 32 <= s.Length; pos += 0x200)
    {
        uint sig = ReadUInt32At(s, pos);
        if (sig == UserDataSignature)
        {
            var ud = MpqUserData.Read(s, pos);  // UserDataSize, HeaderOffset, UserDataHeaderSize, Content
            long headerPos = pos + ud.HeaderOffset;
            if (ReadUInt32At(s, headerPos) == HeaderSignature)
                return (MpqHeader.Read(s, headerPos, options), ud, headerPos);
        }
        else if (sig == HeaderSignature)
            return (MpqHeader.Read(s, pos, options), null, pos);
    }
    throw new InvalidDataException("MPQ header not found.");
}
```

```csharp
internal readonly record struct MpqHashEntry(uint HashA, uint HashB, ushort Locale, ushort Platform, uint BlockIndex)
{
    public const uint Free = 0xFFFFFFFF, Deleted = 0xFFFFFFFE;
}

public static MpqHashEntry[] Read(Stream s, long position, uint count)
{
    var raw = new uint[count * 4];
    ReadExactly(s, position, MemoryMarshal.AsBytes(raw.AsSpan()));
    StormCrypto.DecryptBlock(raw, StormCrypto.HashString("(hash table)", MpqHashType.FileKey));
    // raw → MpqHashEntry[] (Locale/Platform은 3번째 uint의 하위/상위 16bit)
}

// MpqFileTable: 이름 조회 — 저장된 이름은 그대로 두고 구분자만 호환(설계 2절)
public MpqFileEntry? Find(string name, ushort locale = 0) =>
    FindExact(name, locale)
    ?? (name.Contains('/') ? FindExact(name.Replace('/', '\\'), locale) : null)
    ?? (name.Contains('\\') ? FindExact(name.Replace('\\', '/'), locale) : null);

private MpqFileEntry? FindExact(string name, ushort locale)
{
    uint start = StormCrypto.HashStringSlash(name, MpqHashType.TableOffset) & (uint)(_hash.Length - 1);
    uint a = StormCrypto.HashStringSlash(name, MpqHashType.NameA), b = StormCrypto.HashStringSlash(name, MpqHashType.NameB);
    for (uint i = start, n = 0; n < _hash.Length; i = (i + 1) & (uint)(_hash.Length - 1), n++)
    {
        ref readonly var h = ref _hash[i];
        if (h.BlockIndex == MpqHashEntry.Free) break;
        if (h.BlockIndex != MpqHashEntry.Deleted && h.HashA == a && h.HashB == b && h.Locale == locale)
            return _entries[(int)h.BlockIndex];
    }
    return null;
}
```

- `MpqFileFlags`: `Implode=0x100, Compress=0x200, Encrypted=0x10000, FixKey=0x20000, PatchFile=0x100000, SingleUnit=0x1000000, DeleteMarker=0x2000000, SectorCrc=0x4000000, Signature=0x10000000, Exists=0x80000000` (StormLib v9.40 `StormLib.h` 값과 대조함. `FixKey`는 StormLib의 `MPQ_FILE_KEY_V2`)
- `/`로 저장된 이름 샘플이 없으므로 이 단위에서 생성기에 `/` 이름 파일(`v1-zlib.mpq`의 `text/slash.txt`)을 추가하고 샘플을 다시 생성·`verify`한다(StormLib은 `/`를 그대로 저장).

- Compact는 경로로 연 경우 `<경로>.tmp`에 만든 뒤 `File.Replace`로 교체하고 다시 연다. Stream으로 연 경우 임시 파일을 거쳐 내용을 덮어쓴다. 헤더 앞 데이터와 user data는 유지한다.
- 열린 `MpqFileStream`이 있으면 Compact는 `InvalidOperationException`.
- 열린 스트림이 읽는 데이터는 지워진 파일의 것이라도 새 데이터 위치에서 제외한다. 스트림이 모두 닫히면 StormLib `FindFreeMpqSpace`와 같은 배치로 돌아간다.
- 패치 파일(PATCH_FILE)은 삭제·이름변경 대상에서 제외한다. 암호화된 KEY_V2 패치 파일이 있으면 Compact는 `NotSupportedException`이다(단위 18).
- 추가/삭제/이름변경은 열린 스트림이 있어도 허용한다. 기존 데이터를 덮어쓰지 않으므로 열린 스트림은 연 시점의 엔트리(위치·크기·키 복사본)로 계속 읽는다. 데이터 추가·테이블 기록은 `lock (SyncRoot)` 안에서 한다. 암호화 파일 이름변경의 재암호화는 새 위치에 기록한 뒤 엔트리를 교체한다.
- **검증**: `MpqArchiveModifyTests` — 기존 샘플 복사본에 추가/삭제/이름변경 후 재열기 일치, 스트림을 연 채 같은 파일 삭제·이름변경 후에도 열린 스트림 내용 일치, 암호화 파일 이름변경 후 읽기 일치, Compact 후 크기 감소·내용 일치, StormLib verify 일치
- **선행 단위**: 15

## 단위 17. 서명

- **대상**: `Internal/MpqSignature.cs`, `MpqSignatureStatus.cs`, `MpqArchive.VerifySignature/SignWeak`
- **코드 초안**:

```csharp
// RSA는 BigInteger로 직접 계산(512bit 키를 CNG가 거부하는 문제 회피)
static bool VerifyPkcs1(byte[] signatureLe, RsaKey key, ReadOnlySpan<byte> digestInfo)
{
    var s = new BigInteger(signatureLe, isUnsigned: true, isBigEndian: false);
    byte[] em = BigInteger.ModPow(s, key.Exponent, key.Modulus).ToByteArray(isUnsigned: true, isBigEndian: true);
    // 00 01 FF..FF 00 || DigestInfo(MD5) || hash 패딩 검증
}

// weak: (signature) = 8바이트 0 + 64바이트 서명(바이트 역순). 다이제스트는 (signature) 영역을 0으로 둔 MD5(아카이브 시작~ArchiveSize)
// strong: 아카이브 끝 'NGIS' + 256바이트. SHA-1(아카이브 [+ tail]) → 공개키 후보(Blizzard, SC2 map, WoW 등) 순서로 검증
```

- 크기 상수(StormLib `StormCommon.h` 확인): weak 64바이트, `(signature)` 파일 72바이트(64 + 8), strong 256바이트, strong ID `0x5349474E`("NGIS")
- weak 개인키·공개키와 strong 공개키는 StormLib `SFileVerify.cpp`의 PEM 문자열을 상수로 옮긴다.
- 구현은 `Internal/MpqSignature.cs`와 `MpqArchive.Signature.cs`에 있다. StormLib과 같은 점:
  - 서명 범위(`CalculateArchiveRange`)는 MPQ 헤더부터 헤더+ArchiveSize까지이고, 파일이 `HM3W`로 시작하면 파일 처음부터다.
  - 앞 64바이트가 0인 `(signature)`는 검증하지 않고 유효로 본다(`IsValidSignature`).
  - strong 공개키와 SHA-1 꼬리는 Blizzard(없음), W3 맵(대문자 파일 이름), WoW 패치(`ARCHIVE`), WoW 설문(없음), SC2 맵(없음) 순서로 시도한다. Stream으로 연 아카이브는 파일 이름 꼬리가 빈 문자열이다.
  - weak 서명된 아카이브는 수정할 때마다 Flush에서 `(signature)`를 다시 만들고 서명한다(`SSignFileCreate`/`SSignFileFinish`). Compact 뒤에도 다시 서명한다.
  - weak 검증은 StormLib의 libtomcrypt만큼 느슨하다. 0xFF 패딩에 최소 길이가 없고, DigestInfo는 디코드해서 OID와 해시만 비교한다.
- 검증 결과는 `MpqSignatureStatus`로 돌려준다. 이 열거형은 StormLib `SFileVerifyArchive`의 결과 코드에 대응한다.
- PKCS#1 v1.5 서명은 결정적이라, StormLib 샘플의 MD5를 서명한 결과가 샘플의 서명 바이트와 같은지 비교한다.
- **검증**: `SignatureTests` — StormLib weak 서명 샘플 `Valid`, 1바이트 변조 `Invalid`, `SignWeak` 결과를 StormLib verify로 확인, strong은 테스트 전용 2048bit 키 쌍을 주입해 서명→검증
- **선행 단위**: 16

## 단위 18. 패치 아카이브

- **대상**: `MpqArchive.OpenPatchArchive`, `Internal/Patch/PatchFile.cs`, `Internal/Patch/Bsdiff.cs`
- **코드 초안**:

```csharp
// PTCH 헤더: 'PTCH' PatchDataSize SizeBeforePatch SizeAfterPatch | 'MD5_' BlockSize MD5Before MD5After | 'XFRM' XfrmSize Type('BSD0'|'COPY')
public Stream OpenFile(string fileName)
{
    byte[]? data = ReadBaseOrNull(fileName);
    foreach (var patch in _patchChain)                         // 연결 순서대로
        if (patch.TryFindPatch(_patchPrefix(patch) + fileName, out var p))
            data = p.IsPatchFile ? PatchFile.Apply(data, p.Read()) : p.Read();
    return data is null ? throw new FileNotFoundException(fileName) : new MemoryStream(data, writable: false);
}
// BSD0: XfrmSize-0x0C < PatchDataSize-0x44이면 RLE(앞 DWORD 건너뜀, 0x80|(n-1) 리터럴 / n-1 → n개 0) 해제 후
//       'BSDIFF40' 헤더, ctrl(add, extra, oldMove)/diff/extra 블록 적용(diff는 old 바이트에 더함), MD5After 검증
// COPY: 헤더 뒤 데이터가 그대로 새 파일
```

- prefix 생략 시 StormLib처럼 베이스 아카이브의 접두 후보(`enUS\`, `base\` 등)를 패치 아카이브에서 탐지한다.
- 구현은 `MpqArchive.Patch.cs`와 `Internal/Patch/MpqPatch.cs`(초안의 `PatchFile.cs`·`Bsdiff.cs`를 하나로 합침)에 있다. 패치 파일 데이터 앞의 TPatchInfo는 `MpqSectorReader`가 건너뛴다.
- 접두 탐지는 StormLib `FindPatchPrefix`를 옮겼다:
  - WoW: 패치에 `base\(patch_metadata)`가 있으면, 기준 아카이브의 `*-####-md5.lst`에서 언어를 찾고 없으면 `Base`를 쓴다.
  - SC2: 기준 아카이브에 `StreamingBuckets.txt`가 있으면, 아카이브 경로(Battle.net·Campaigns·Mods) → `<경로>-PATCH` 도우미 파일 → `(patch_metadata)` 옆 파일의 MD5 비교 순으로 찾는다.
  - 그 밖에는 빈 접두다.
- 체인 해석(`OpenPatchedFile`): 체인에서 패치가 아닌 마지막 버전이 원본이다. 마지막 버전에 DELETE_MARKER가 있으면 파일이 없는 것으로 본다. 다음 패치의 md5_before가 현재 MD5와 같으면 현재 패치를 건너뛴다(`Patch_Process`).
- StormLib과 다른 점:
  - COPY: StormLib `ApplyFilePatch_COPY`는 이전 버전을 복사하는 버그가 있다. 여기서는 헤더 뒤 데이터를 새 파일로 쓴다.
  - 손상된 패치: StormLib은 0바이트를 돌려주지만 여기서는 `InvalidDataException`이다.
- 패치 파일(`MPQ_FILE_PATCH_FILE`)은 패치 체인 밖에서 일반 파일로 열지 않는다(StormLib 동일).
- **검증**: `PatchTests` — 생성기 BSD0 패치 체인(`patch-base.mpq` + `patch-1.mpq`)이 `patch-1.mpq.expected.json`과 일치, COPY는 StormLib가 추가 시 패치 파일로 인식하지 않아 샘플이 없으므로 테스트에서 직접 만든 PTCH(COPY) 데이터로 `PatchFile.Apply` 결과 확인, MD5 불일치 시 예외
- **선행 단위**: 17
