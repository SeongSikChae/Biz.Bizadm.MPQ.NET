# MPQ 라이브러리 방안

## 배경

`Biz.Bizadm.MPQ.NET` 저장소는 빈 `.slnx`(src/, tests/ 폴더)만 있는 상태다. 다음 자료를 참고해
MPQ(MoPaQ) 아카이브를 읽고 쓰는 C# 클래스 라이브러리를 만든다.

- mpyq: https://github.com/eagleflo/mpyq
- sc2-file-format-docs (mpq-format.md): https://github.com/sc2-arcade-watcher/sc2-file-format-docs/blob/main/mpq-format.md
- StormLib: https://github.com/ladislav-zezula/StormLib
- s2protocol (tutorial_API.rst): https://github.com/Blizzard/s2protocol/blob/master/docs/tutorial_API.rst

## 문제·목표

- .NET 10에서 MPQ 아카이브를 열어 파일 목록 조회·추출, 새 아카이브 생성, 기존 아카이브 수정까지 하는 관리 코드 라이브러리를 제공한다.
- 1차 대상은 SC2 리플레이/맵(`.SC2Replay`, `.SC2Map`)과 Blizzard 클래식 MPQ다.

## 범위

| 항목 | 결정 |
|---|---|
| 쓰기 | 새 아카이브 생성 + 기존 아카이브 파일 추가/삭제/이름변경 + compact |
| 포맷 | v1~v4 전체(Hash/Block, Hi-block, HET/BET, MD5 헤더) + SC2 User Data 헤더(`MPQ\x1B`) |
| 압축 | zlib, bzip2, LZMA, PKWARE implode/explode, Huffman, ADPCM(mono/stereo), sparse, 다중 압축 마스크 |
| 암호화 | Storm 암호 테이블, 파일 키(FIX_KEY 포함), 해시/블록 테이블 암·복호 |
| 부가 | `(listfile)`/`(attributes)` 자동 관리, `(signature)` 검증(weak/strong, 쓰기는 weak), PTCH 패치 아카이브 체인, 손상·보호 아카이브 관대한 읽기 |
| 의존성 | 검증된 NuGet 허용(bzip2·LZMA 후보). zlib은 BCL `ZLibStream`. 패키지 선정은 `dotnet-nuget-package` 규칙(TFM 호환·최신 패치·비취약)을 따른다 |
| 구성 | `src/Biz.Bizadm.MPQ.NET`(classlib, net10.0) + `tests/Biz.Bizadm.MPQ.NET.Tests`(MSTest), `Directory.Build.props`/`Directory.Packages.props`(CPM) |

## 비범위

- s2protocol(리플레이 내용 디코딩: details/events 등). 별도 프로젝트로 분리하며, 본 라이브러리는 파일 바이트 추출까지 담당한다.
- CASC 등 MPQ 이후 저장 포맷.
- strong 서명 생성(Blizzard 개인키 필요).

## 채택 방안 개요

설계 단계에서 구체화한다.

- 공개 API
  - `MpqArchive`: Open/Create, 파일 열거·존재 확인·추출 Stream, 추가/삭제/이름변경/Compact
  - `MpqFileStream`: 섹터 단위 지연 해제
  - `MpqArchiveCreateOptions`: 포맷 버전, 섹터 크기, 해시 테이블 크기
- 내부 계층: 헤더/User Data 파서 → 테이블(Hash/Block/HiBlock/HET/BET) → 암호(StormCrypto) → 압축 코덱 레지스트리 → 섹터 리더/라이터
- 설계 단계 결정 사항: 수정 시 임시 파일에 재작성 후 교체할지, in-place로 추가할지
