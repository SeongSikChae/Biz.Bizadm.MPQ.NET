# MPQ 라이브러리 설계

선행 문서: `docs/mpq/0001-MPQ라이브러리-방안.md`

## 1. 공개 API·쓰기 정책

### 결정

| 항목 | 결정 |
|---|---|
| 수정 방식 | 혼합. 추가/삭제/이름변경은 in-place(데이터는 아카이브 끝에 추가, 테이블만 재기록), Compact는 임시 파일에 재작성 후 교체 |
| I/O 모델 | Stream 기반 동기 API. async API는 제공하지 않는다 |
| 쓰기 버전 순서 | 개발 단위를 v1 → v2 → v3 → v4 순으로 나눈다(범위는 v1~v4 동일) |
| 스레드 안전성 | 읽기 동시성만 보장(여러 파일 스트림 동시 읽기, 기반 스트림 접근은 lock). 쓰기는 단일 스레드 |

### 공개 형태(초안)

```csharp
public sealed class MpqArchive : IDisposable
{
    public static MpqArchive Open(string path, MpqOpenMode mode = MpqOpenMode.Read, MpqOpenOptions? options = null);
    public static MpqArchive Open(Stream stream, MpqOpenMode mode = MpqOpenMode.Read, bool leaveOpen = false, MpqOpenOptions? options = null);
    public static MpqArchive Create(string path, MpqArchiveCreateOptions? options = null);
    public static MpqArchive Create(Stream stream, MpqArchiveCreateOptions? options = null, bool leaveOpen = false);

    public MpqHeader Header { get; }
    public MpqUserData? UserData { get; }
    public IEnumerable<MpqEntry> Entries { get; }

    public bool Contains(string fileName);
    public Stream OpenFile(string fileName);

    public void AddFile(string fileName, Stream content, MpqAddFileOptions? options = null);
    public void DeleteFile(string fileName);
    public void RenameFile(string oldName, string newName);
    public void Flush();
    public void Compact();
}
```

- `MpqFileStream`: 읽기 전용, Seek 가능, 섹터 단위 지연 해제(필요한 섹터만 읽어 복호·해제).
- 기반 Stream 접근은 아카이브 단위 lock으로 직렬화해 여러 `MpqFileStream`의 동시 읽기를 허용한다.
- in-place 수정: 새 파일 데이터는 현재 데이터 끝(테이블 앞 또는 뒤)에 기록하고, `Flush()`/`Dispose()` 시 해시·블록 테이블과 헤더를 재기록한다. 삭제는 해시 엔트리를 삭제 표시(0xFFFFFFFE)로 바꾸고 블록은 Compact 전까지 남긴다.
- 열린 스트림과 수정: `MpqFileStream`이 열려 있어도 추가/삭제/이름변경을 허용한다. in-place 수정은 기존 파일 데이터를 덮어쓰지 않으므로 열린 스트림은 연 시점의 데이터를 계속 읽는다. 테이블·헤더 기록과 데이터 추가는 읽기와 같은 `SyncRoot` lock 안에서 한다.
- Compact: 유효 파일만 임시 파일에 다시 쓰고 원본과 교체한다(Stream으로 연 경우는 Stream 내용을 덮어쓰고 길이를 조정한다).

## 2. 포맷 구조·테이블·코덱

### 결정

| 항목 | 결정 |
|---|---|
| 파일 테이블 | 통합 파일 테이블. Hash/Block/HiBlock/HET/BET를 읽어 하나의 `MpqFileEntry` 목록으로 합치고, 저장 시 헤더 버전에 맞게 다시 분해한다 |
| bzip2·LZMA | SharpCompress 사용. 버전·취약점 확인은 개발 단계에서 `dotnet-nuget-package` 규칙대로 한다 |
| 레거시 코덱 | StormLib(MIT)의 PKWARE implode/explode, Huffman, ADPCM, sparse를 C#으로 포팅한다(압축·해제 양방향). 라이선스 고지를 포함한다 |
| 쓰기 기본값 | 압축 zlib, 섹터 4096(shift 3), 암호화 없음, 파일명 UTF-8. `MpqAddFileOptions`/`MpqArchiveCreateOptions`로 변경 가능 |
| 이름 저장·조회 | 저장은 받은 이름 그대로(StormLib 동일, 구분자를 바꾸지 않음). 조회는 `\`·`/` 둘 다 호환: ① 입력 그대로 → ② `/`→`\` → ③ `\`→`/` 순으로 찾는다. 해시는 ASCII 대소문자만 무시하고 구분자는 바꾸지 않는 `HashStringSlash`(StormLib v9.40 기본)를 쓴다. 파일 키는 경로를 뺀 이름으로 계산하므로 구분자와 무관하다 |

### 계층

```
MpqArchive (공개)
 ├─ MpqHeaderReader/Writer : User Data(MPQ\x1B) 탐색, 헤더 v1~v4(32/44/68/208 bytes), 512바이트 경계 탐색
 ├─ MpqFileTable           : List<MpqFileEntry> (통합)
 │   ├─ HashTableSerializer   : v1~ (암호 키 "(hash table)")
 │   ├─ BlockTableSerializer  : v1~ (암호 키 "(block table)") + HiBlock(v2~)
 │   └─ HetBetSerializer      : v3~ (HET/BET, Jenkins hash)
 ├─ StormCrypto            : 암호 테이블(0x500), HashString(type 0~3), Encrypt/DecryptBlock, 파일 키(FIX_KEY)
 ├─ MpqCompression         : 압축 마스크 디스패치(다중 압축 순서), 코덱 레지스트리
 │   └─ Codecs: Zlib(BCL), BZip2/Lzma(SharpCompress), Pkware, Huffman, Adpcm, Sparse
 └─ MpqSectorReader/Writer : 섹터 오프셋 테이블, sector CRC, single-unit, 섹터별 압축·암호
```

### 데이터

```csharp
internal sealed class MpqFileEntry
{
    public string? FileName { get; set; }   // listfile로 해석된 이름(없으면 null)
    public ulong NameHash { get; set; }      // HET/Jenkins 64bit
    public uint HashA { get; set; }          // Storm hash type 1
    public uint HashB { get; set; }          // Storm hash type 2
    public ushort Locale { get; set; }
    public ushort Platform { get; set; }
    public long FilePosition { get; set; }   // 아카이브 시작 기준 상대 오프셋(64bit)
    public uint CompressedSize { get; set; }
    public uint FileSize { get; set; }
    public MpqFileFlags Flags { get; set; }
}
```

- 이름 없는 엔트리(listfile에 없음)는 `File00000001.xxx` 형태의 가상 이름으로 열람만 가능하다(StormLib 동작과 동일).
- 이름 정책 근거: MPQ 형식은 구분자를 강제하지 않고 만든 도구가 넘긴 문자열을 그대로 해시한다. Blizzard 도구로 만든 아카이브는 `\`를 쓰고(StormLib `test/StormTest.cpp:4195`의 실제 w3x 맵 이름 해시가 `\` 형태와 일치, `/` 형태와 불일치), StormLib은 생성·열기 모두 `HashStringSlash`(`SFileCreateArchive.cpp:212`, `SFileOpenArchive.cpp:268`)라 Linux 등에서 `/`로 넣으면 `/`로 저장된다.
- 해시 테이블 충돌은 선형 탐사, 빈 슬롯(0xFFFFFFFF)에서 중단, 삭제 슬롯(0xFFFFFFFE)은 건너뛴다.

## 3. 부가 기능·검증

### 결정

| 항목 | 결정 |
|---|---|
| `(listfile)`/`(attributes)` | Flush 시 자동 갱신. 아카이브에 해당 파일이 있거나 생성 옵션이 켜져 있으면 추가/삭제/이름변경을 반영해 다시 쓴다. 외부 listfile 추가(`AddListFile`) 지원 |
| 패치 아카이브 | OpenPatch 체인. `archive.OpenPatchArchive(path, prefix)`로 순서대로 연결하고, `OpenFile`이 체인을 따라 PTCH(BSD0/COPY) 패치를 적용한 결과를 반환한다. 읽기 전용 |
| 관대한 읽기 | 기본 켜짐. 잘못된 테이블 크기·범위 밖 블록·가짜 헤더를 보정해 읽는다. `MpqOpenOptions.Strict`면 검증 실패 시 예외. 관대 모드에서 보정이 일어난 아카이브는 쓰기를 금지한다 |
| 서명 | `(signature)` weak(512bit RSA, MD5) 검증·생성, strong(`NGIS`, 2048bit RSA, SHA-1) 검증. 공개키는 StormLib에 포함된 Blizzard 공개키를 사용한다. weak 서명 생성은 StormLib에 공개된 weak 개인키를 사용한다 |
| 테스트 데이터 | StormLib로 생성한 샘플 아카이브와 교차 검증한다. 버전(v1~v4)·압축별 샘플을 `tests/Biz.Bizadm.MPQ.NET.Tests/TestData`에 둔다. 확보 방법(네이티브 StormLib 빌드 후 생성기 작성 등)은 개발 단계에서 정한다. 자체 쓰기 결과는 라운드트립과 StormLib 읽기로 확인한다 |

### 공개 형태(초안)

```csharp
public sealed class MpqOpenOptions
{
    public bool Strict { get; init; }                 // 기본 false(관대한 읽기)
    public IEnumerable<string>? ExternalListFile { get; init; }
}

public sealed class MpqArchiveCreateOptions
{
    public MpqFormatVersion FormatVersion { get; init; } = MpqFormatVersion.Version1;
    public int SectorSizeShift { get; init; } = 3;     // 512 << 3 = 4096
    public int HashTableSize { get; init; } = 0x1000;  // 2의 거듭제곱
    public bool CreateListFile { get; init; } = true;
    public bool CreateAttributes { get; init; } = true;
}

public sealed class MpqAddFileOptions
{
    public MpqCompressionType Compression { get; init; } = MpqCompressionType.Zlib;
    public bool Encrypt { get; init; }
    public bool FixKey { get; init; }
    public bool SingleUnit { get; init; }
    public bool SectorCrc { get; init; }
    public ushort Locale { get; init; }
    public bool Overwrite { get; init; }
}

// MpqArchive 추가 멤버
public void AddListFile(IEnumerable<string> fileNames);

public MpqSignatureStatus VerifySignature();
```
